集群单位：单兵 Bot 与集群指挥 Bot

集群单位是成批存在、没有独立上下文的单位。它分两层：集群指挥 Bot 维护区域级态势、下达集群订单； 单兵 Bot 只做局部感知与逐格执行。LLM 最多指挥一个集群，不会也不该逐单位下指令。

1:N 批量 单兵 Bot 集群指挥 Bot 聚合上下文 流场移动 确定性推进
集群指挥 区域与订单 上层意图 来自角色或盟主 单兵 局部执行 交战 与攻城 撤退 与消亡

1集群是什么

判据只有一条：有没有独立上下文。没有，就是集群。

与角色单位的边界

维度角色单位集群单位
对应关系一个角色一个 LLM，一人一份上下文一批单位共用一个决策源，不逐个体分配 LLM
决策来源自己的上下文 + 记忆 + 频道历史集群指挥 Bot：规则或单个 LLM，输入是聚合态势
排期进 claimTrigger，按玩家发言、关键点、随机时间触发按 Tick 推进；指挥层按阶段或关键点重评估
订单姿态 + 目标格，针对个体姿态 + 目标区域，作用于整批
寻路逐个体 A*每同盟一张流场 + 局部避让，不逐单位寻路
数量级每同盟个位数每同盟几十到上千
记忆与频道有记忆、会发言无记忆、不发言，只回传聚合信号
失败处理回退到该角色的模拟决策不涉及 LLM；指挥层是 LLM 时回退到规则型
当前实现里小兵就是集群单位：主城每 20 Tick 生成 3 个，单同盟存活上限 15， 不入角色排期、不产订单、每个单位没有上下文。

2两层 Bot

指挥层看区域，单兵层看脚下；两者都用状态机，但时钟与输入完全不同。

控制层级

上层意图

角色单位 / 盟主

只说「去哪、做什么」，例如夺取某个关口或守住某段城墙，不给路径也不给队形。

集群指挥 Bot

每集群一个 · 秒级

维护聚合态势，把意图分解成区域级订单，决定推进方向、分批与撤退时机。

单兵 Bot

每单位一个 · 每 Tick

局部感知、跟随流场、避让邻居、交战与攻城；不读全局地图，不做战略判断。

信息如何下沉 意图只到区域，路径由执行层决定

三个单兵方框表示同一个集群的多批单位，不是三个不同种类。集群指挥 Bot 每批只下一次区域级订单， 单兵自行按流场走位；纠纷由局部规则解决，不回到指挥层。

3集群指挥 Bot

它的输入是聚合态势，输出是区域订单；不需要知道每个单兵在哪一格。

职责

项负责不负责
目标选定目标区域与推进方向逐格路径与绕障
分批决定几股推进、哪股佯攻、哪股留守单个单位的站位
时机何时压上、何时撤退、何时补员逐单位攻击目标选择
补给维持存活数与补员节奏资源逐笔计费

两种实现 规则型是默认，LLM 型只用于玩家同盟的盟主或大臣

项规则型LLM 型
输入阶段（开荒 / 筑垒 / 进攻）+ 敌方主城 + 存活数聚合态势 + 玩家或盟主的指令
输出集群订单集群订单 + 一句话发言（进同盟频道）
触发每 N Tick，或阶段切换关键点 + 随机时间，与角色排期同构
调用量0每集群一次，不随单位数增长
失败—超时或非法输出回退规则型，订单照发
适用后台势力、RPG 杂兵玩家同盟的盟主、大臣
LLM 型指挥 Bot 与角色单位复用同一套回退链，区别只在上下文是聚合的： 它看得到「这一股还剩多少人、卡在哪个关口」，看不到「某个小兵站在第几格」。

指挥状态机 集群级状态，与单兵状态无关

交战与围城之间可来回切换：贴城即围城，守军出城则回交战。 撤退分两种——订单撤退（保存兵力）与被动溃退（减员过多），都回到集结。

4集群单兵 Bot

每个单位一个实例，但它没有记忆、没有上下文，只有状态与局部邻居。

感知与移动

项做法理由
感知范围周边 1 格 + 少量邻居查询不读全局地图，避免每单位全图扫描
寻路每同盟一张流场，单兵只查当前格的下降方向千级单位共享一次计算，避免逐单位 A*
避让同格冲突时按规则让位（先到先得 + 随机抖动）用局部规则替代全局调度
节奏每 Tick 最多走 1 格，地形耗时与角色一致与推演节拍同频，便于快照对齐
随机数只从公共种子流按固定顺序取保证同存档可复现

单兵状态机

状态怎么进入当 Tick 做什么 / 怎么离开
出生 spawn主城按节奏生成，或补员补充落到出生格并转入行军
行军 march有目标区域按流场走 1 格；到达区域边缘转交战或攻城
交战 engage同格或相邻出现敌对单位固定 7 点伤害，每 Tick 一次；敌军消失回到行军
攻城 siege相邻敌对主城每 Tick 削 8 点城防，归零后主城改归属并写入战报
撤退 retreat集群订单撤退，或减员超过阈值沿流场反向退回本州，转入补员
消亡 dead兵力归零回收实例，只向指挥层回传一条减员计数
单兵没有「休整」「筑垒」「占领」这些角色专属状态：它不会占领地块，也不修要塞； 主城归属只由小兵攻城改变，角色不占领主城格。

5信息流

下行只到区域，上行只回聚合。

上下行信号

方向内容频率
下行角色意图 → 集群指挥 Bot → 区域订单 → 单兵意图变化时，或指挥层重评估时
上行减员、受阻、抵达区域、城防进度单兵只报事件，指挥层聚合
关键点集群被全灭、目标区域易手、城防归零聚合后上报角色单位的排期
单兵不发言、不进频道、不进任何 LLM 上下文。角色看到的永远只是聚合结果， 这样角色上下文的大小与集群规模无关。

6规模与性能

集群的瓶颈在推演与渲染，不在决策；逐单位 LLM 在数量上就不成立。

实测推演耗时 现有实现，未优化

规模每 Tick 耗时主要开销
1008.5ms逐单位 A* 与距离计算
30030.9ms同上，随数量平方增长
1000177.7ms交战 O(n²)、全量目标扫描、逐 Bot 寻路
优化路径依次是：交战改网格索引消掉平方项 → 每同盟一张流场替代逐单位 A* → 快照改增量 → 渲染改 InstancedMesh 且只绘制视口内标签。

8与角色单位的接口

允许与禁止

方向规则
角色 → 集群角色只给「目标区域 / 要做什么」，由集群指挥 Bot 转成区域订单
集群 → 角色只回传聚合信号与关键点，不把每个单兵写进角色上下文
禁止一个 LLM 逐单位下指令；集群单位进入角色频道；集群单位拥有独立记忆
例外剧情需要时，单个集群单位可临时升格为角色单位，但必须新分配上下文与排期
角色单位见《角色单位与决策层》，规则的文字来源见《角色系统/角色行动.md》。
