Bot 状态机与 LLM 介入

Bot 负责逐 Tick 的行军、占领、交战、筑垒与休整，全部在服务端确定性推进； LLM 只在决策点写入一份「姿态 + 目标格」的订单，不介入路径与结算。两张图分别说明状态怎么切换、LLM 从哪里进来。

2LLM 如何介入 Bot

三层结构固定，LLM 只在决策层活动，落点只有一个写指令的接口。

三层控制架构

指挥层

盟主（玩家或 LLM）

提出方向、目标与要求，作用是改变决策层的输入，不直接改指令。

决策层

LLM + 角色属性

以角色身份理解局势，产出「一句话发言 + 若干条订单」，每 Tick 每个角色至多一次。

执行层

Bot 状态机

寻路、逐格行军、占领、遭遇战、筑垒、休整，严格按订单执行，不做战略判断。

介入链路一次决策到下一次行动

  1. 世界回合循环 advance() 每 Tick 调用 sim.step()，Bot 状态机逐单位推进；推演结束发出回合信号。
  2. RoundGate 放行 广播回合号，所有停在 await 的角色协程在同一边界恢复。
  3. 角色协程 tick() claimTrigger() 按优先级判定本回合是否决策：玩家发言 > 关键点 > 随机时间 > 世界发言。
  4. buildActorContext() 自身上下文（自己的指令与发言）+ 环境上下文（三个频道最近发言）+ 可见战况（单位、候选、资源）。
  5. LLM 或模拟 LLM 输出 JSON { reply, orders }；超时、解析失败或未配置 API 时回退模拟 LLM，格式不变。
  6. applyOrders() → sim.setOrder() 订单写入单位，下一个 Tick 由 Bot 状态机接管；reply 落到触发来源对应的频道。

触发时机

玩家发言

最高优先级

立即唤醒、不等回合边界，令牌队列插到队首；不计入发言配额。

关键点

局势变化

遭遇战、占领成功、战败、行军受阻、失地、要塞失守；距上次不少于 20 回合，期间合并。

随机时间

自主决策

开启自动决策时生效，基准间隔的 0.5 ~ 1.5 倍随机，各角色独立排期。

世界发言

仅发言人

每同盟按职位选一名发言人，约 20 回合一次；只出声，不下指令。

介入边界

项规则
介入点只有一个：sim.setOrder()。LLM 给的是「姿态 + 目标格」的订单，不是逐格路径
姿态attack / defend / hold / retreat / buildFortress / auto，决定下一 Tick 走向哪条状态分支
寻路不介入：A* 由执行层计算，自动绕开不可通行地形与敌方已建成要塞
行军与占领不介入：逐格移动、地形耗时、占领进度全部由 sim.step() 推进
战斗不介入：同格或相邻即自动交战，普攻、伤害浮动与胜负结算不询问 LLM
工事与资源不介入：建造进度、拆要塞、扣料与补兵计费由推演层结算；资源不足只回传信号
发言只写文本：reply 进对应频道，受每频道每回合 1 条配额限制
推进权留在世界回合循环：状态机不在角色协程里跑，保证寻路与遭遇战的随机数消费顺序不随协程调度漂移，同一存档可复现同一战报。
依据代码：src-server/game/bot/simulation.ts 的 act() / captureTile() / followOrder() / defeat() / disengage()， src-server/game/agent/actor.ts 的 claimTrigger() / decide() / apply()， src-server/runtime/GameRuntime.ts 的 advance() / dispatchSignals() / applyOrders()。 规则文本见《角色系统/角色行动.md》。
