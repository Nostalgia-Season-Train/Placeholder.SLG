# 角色系统

> 核心玩法系统。系统的唯一职责是：让每个角色自行观察、判断、决策并驱动 Bot，与玩家和其他角色对话。
> 本文写这套系统的完整规格：角色怎么被扮演、什么时候决策、上下文取自哪里，以及协程怎么跑。玩法层面的写法另见《概览》，角色属性字段见《角色属性》，地图与推演规则见《大地图行军推演》，同盟关系见《同盟关系》。

---

## 概览

玩家扮演盟主，不逐格操作部队。地图上的每一名角色都是一个独立的行为主体：Bot 负责他的行军、占领、遭遇战与休整，LLM 负责他的判断与语气。

每个同盟都有自己的盟主。玩家所在的同盟由玩家担任盟主；其他同盟的盟主由 LLM 扮演，和普通角色一样有自己的协程、记忆与排期，向本同盟的大臣、团长下达方向。盟主是决策层的最高一层，不亲自带兵。

每名角色在自己的协程里循环：

```
等待回合 → 判断是否该思考 → LLM 决策 → 下达指令与发言 → Bot 按指令行动 → …
```

角色什么时候思考，看随机时间和关键点这两件事：平时按自己的节奏排期，不会每回合请示；遭遇战、目标失效、被夺地这类需要上层判断的变化，会立刻把他叫醒。

角色的判断来自角色属性：职位决定他能指挥谁，定位决定他是否亲自带兵，性格决定他倾向冒险还是保守。同一句军令，谨慎的大臣会先问补给，勇猛的武将直接点兵出发。

交流发生在频道里。世界频道是所有同盟的公开场合；同盟频道每个同盟各有一个，只有本同盟的盟主与角色能发言，玩家只能进入自己同盟的那个；本团频道是玩家核心团专属，由绝对忠于玩家的角色回应，军令必然照办。对话是聊天式的，不排队、不互斥。

LLM 只能决定「做什么、说什么」，具体的路怎么走、地怎么占、仗怎么打，全部由 Bot 按地图规则完成。未配置 LLM 时，同一套输入输出结构改由本地模拟 LLM 产出，推演不中断。

玩家、LLM、Bot 的定义见《概览》术语一节。

## 1. 系统定位

| 项 | 内容 |
| --- | --- |
| 名称 | 角色系统 |
| 一句话 | 每个角色一个协程，按「决策 → 行动 → 触发 → 决策」自主循环，LLM 扮演角色并有记忆 |
| 负责 | 角色身份与扮演、决策时机、上下文与记忆、LLM 调用与降级、频道发言、行动指令的形成 |
| 不负责 | 地图生成、寻路与行军规则、遭遇战结算、存档格式、外交配色 |
| 输入 | 角色属性、可见局势、频道消息、关键点事件、玩家发言 |
| 输出 | 行动指令（交给 Bot）、频道发言、频道上下文（给其他角色和玩家看） |

系统分三层，后两层合称**角色行动**：角色行动 = LLM 决策 + Bot 执行。玩家指挥不在其中，三层各管各的：

| 层 | 承担者 | 是否属于角色行动 | 职责 |
| --- | --- | --- | --- |
| 指挥层 | 盟主（玩家或 LLM） | 否 | 提出方向、目标与要求，作用是改变决策层的输入 |
| 决策层 | LLM + 角色属性 | 是 | 以角色身份理解局势、决定怎么做、决定说什么 |
| 执行层 | Bot | 是 | 寻路、行军、占领、遭遇战、休整，严格按指令行动，不做战略判断 |

玩家在频道里的发言不算角色行动，它只是 LLM 决策的一条外部输入。玩家直接控制核心团 Bot 则算：这一下越过决策层，直接改写执行层的指令。

决策层不碰地图，执行层不做战略判断。角色之间的差别来自属性和提示词，Bot 的代码里没有这些分支。

**所有角色一律「Bot 驱动 + LLM 决策」，没有哪条通道能绕过 LLM。** 差别只写在角色属性的提示词里；玩家直控核心团 Bot 是操作功能，不是角色通道。

## 2. 角色协程

### 2.1 为什么用协程

系统运行在 Node 单线程事件循环上，每个角色一个长期存活的 `async` 协程：

- 协程在 `await` 处让出，其他协程与世界回合循环照常运行，一个角色思考不会卡住其他角色
- 角色数量在几十量级，协程是函数挂起，开销远小于线程，也不需要处理共享内存同步
- 同一角色的决策在自身协程内逐次推进，天然串行，不会出现同一角色两路决策并发

这里真正的瓶颈是等 LLM 回包，不是算力，协程够用；线程留给真需要 CPU 并行的场合。

### 2.2 角色与 Bot 单位的对应

每个**角色**各一个协程，与它是否在地图上带兵无关：

| 角色 | 是否有 Bot 单位 | 协程职责 |
| --- | --- | --- |
| 盟主 | 否，坐镇 | 观测全同盟态势，向大臣与团长下达方向；玩家同盟的盟主是玩家本人，不跑协程 |
| 大臣 | 否，坐镇 | 观测同盟态势，产出指令给团长与团员 |
| 团长 | 否，坐镇 | 观测本团态势，产出指令给本团团员 |
| 武将 / 术武将（无职位） | 是，自身单位 | 驱动自身单位，在关键点请求决策 |
| 法师 / 疗愈师（无职位） | 不统兵 | 只做支援与发言，不下达带兵指令 |

### 2.3 循环骨架

每个角色循环执行

```
LLM 决策 → Bot 驱动（状态机）→ 关键点或随机时间 → LLM 决策 → …
```

```ts
async function runActor(actor: Actor) {
  while (actor.alive && actor.worldAlive) {
    // ① 等待回合边界：世界回合循环每 tick 广播一次
    const round = await actor.waitForRound()

    // ② 取本回合的关键点并判定是否该决策
    const trigger = actor.takeTrigger(round)

    // ③ 决策：关键点优先，其次随机时间到
    if (trigger !== null) {
      const context = buildContext(actor, trigger)      // 自身上下文 + 环境上下文
      const decision = await actor.llm.decide(context)  // 协程内 await，不阻塞世界
      applyDecision(actor, decision)                    // 写指令、写频道、记入自身记忆
    }

    // ④ 该角色的 Bot 状态机推进由世界回合循环完成（见 2.4）
  }
}
```

### 2.4 两条循环的分工

世界上有两个独立循环，职责不重叠：

| 循环 | 持有者 | 职责 |
| --- | --- | --- |
| 世界回合循环 | `GameRuntime.advance` | 推进 `sim.step()`，按固定顺序让所有 Bot 走一步，广播回合信号 |
| 角色协程 | 每个角色 | 判定决策时机、组装上下文、调用 LLM、写回指令与发言 |

**为什么 Bot 推进不放进各自协程**：`sim.step()` 必须按固定顺序串行推进，否则寻路与遭遇战的随机数消费顺序会随协程调度漂移，战报无法复现、存档也对不齐。因此推进权留在世界回合循环，角色协程只通过 `setOrder()` 施加影响，两者在回合边界同步。

若后续要求 Bot 推进也由各自协程执行，必须同时满足「固定调度顺序」与「把每个协程的挂起点写入存档」，这是本方案主动放弃的复杂度，见第 11 节。

### 2.5 挂起与恢复

| 事件 | 处理 |
| --- | --- |
| 暂停推演 | 世界回合循环停止广播，所有协程停在 `await waitForRound()` |
| 继续推演 | 恢复广播，协程按各自顺序恢复 |
| 重置 / 读档 | `runId + 1`，向所有协程投递取消哨兵并退出，按新存档重建协程 |
| 服务端关闭 | `dispose` 批量取消，在途请求超时或中止 |
| 新增角色 | 新建协程，`nextDecisionRound = 0`，进场即随机排期 |

## 3. 角色扮演

### 3.1 对话关系，而非命令执行

LLM 扮演的是同盟里的一名角色，与盟主之间是**对话关系**：

- 盟主在同盟频道的发言是一次对话，角色的回应可以是执行、讨论、质疑、婉拒甚至讨价还价
- 角色是否把话语转化为行动，由角色按自身立场、职位与性格判断
- 对话不排队、不互斥：连续发言、自动决策与频道播报可以同时进行，回执按各自完成顺序进入频道，节奏类似聊天软件里一问一答
- 系统不设「LLM 忙碌」状态，不会因为角色正在思考而拒绝玩家发言
- 例外只体现在**提示词里的身份设定**上，不体现在通道上

### 3.2 扮演依据

| 角色属性字段 | 对决策的约束 |
| --- | --- |
| 名称、描述 | 说话口吻、立场与用词 |
| 职位 | 可指挥的范围：大臣指挥同盟，团长指挥本团 |
| 定位 | 行为边界：武将、术武将可前线带兵；法师、疗愈师不统兵 |
| 攻击、魔力 | 判断自身能承担的战斗强度 |
| 性格 | 侵略性、谨慎度等倾向，同时影响 Bot 行为树的触发概率 |
| 对话提示词 | 发言风格与称呼，不影响行动判断 |
| 作者注释 | 不进入上下文，对系统不可见 |

扮演规则：

- 发言使用角色自身口吻，同一同盟的不同角色不共享同一套语气
- 决策不得越过定位限制，不统兵的角色不会下达带兵指令
- 职位决定决策的影响面：大臣的决策可要求团长行动，团长的决策只作用于本团团员
- 角色只能感知自己可见的信息，不读取全图状态

**性格的两层作用**：

| 层 | 作用方式 |
| --- | --- |
| Bot 行为树 | 按标签映射为行为概率，例如懦弱的疗愈师在大军压境时提高撤退概率 |
| LLM 扮演 | 决策与发言保持人设一致，不做出与性格明显冲突的判断 |

**逃跑类行为的 LLM 介入**：触发前由 LLM 判断是否逃跑，并把判断与发言写入同盟频道（告急、求援）；触发后由 LLM 判断是否强行介入、重回前线。介入只覆盖当次行为，不修改性格标签本身。

### 3.3 核心团的忠诚约束

核心团不是绕过 LLM 的特殊通道，而是一批**提示词里写明忠诚**的角色：

- 核心团角色的系统提示词追加约束：绝对忠于盟主，军令无条件执行，不得质疑、拒绝或讨价还价，回应中要明确表示已经照办
- 玩家在本团频道发言时，走的仍是同一条 LLM 扮演与决策通道，只是角色一定会照办
- 同盟其他角色的提示词不含该约束，可以照办，也可以提出异议、要求补给或直接拒绝
- 两类角色共用同一套输入输出结构，差别只在提示词，不在代码通路
- 无可用 LLM 时两类角色都回退模拟 LLM，保证推演不中断

### 3.4 大地图直接指挥 Bot

「直接指挥」是大地图上的操作功能，不是频道对话：

- 玩家在地图上选中绿色（我方核心团）角色，直接下达 Bot 级操作：移动、进攻、驻守、待命、撤退
- 复用决策层可用的同一套 Bot 能力，直接写入行动指令，不经 LLM 对话往返
- 适合救急：某名角色即将被围时，玩家不等角色思考，直接把它拉回来
- 只改变该角色当次目标，不改变角色属性设定与性格；指挥结束后角色仍按自身逻辑继续行动
- 与频道的关系：频道是「与角色对话、由角色决定怎么做」，地图直控是「玩家自己动手改指令」，两者最终落到同一份行动指令结构上
- 当前尚未实现

### 3.5 玩家可见的频道

对话与指令只发生在世界、同盟、本团三个频道，不存在独立的指挥界面。发言作者按「【同盟名】职务·角色」格式显示，无职务时省略职务段。

每个同盟都有一个同盟频道，由该同盟的盟主与角色使用。玩家的同盟频道对本方角色开放；其他同盟的频道由各自的 LLM 盟主与角色使用，玩家不可发言，也不读取其内容——那些对话只通过世界频道的公开发言与地图上的行动体现出来。核心团不再单设盟主，它属于玩家同盟，玩家即盟主。

| 频道 | 归属 | 参与方 | 是否影响 Bot |
| --- | --- | --- | --- |
| 世界 | 公共 | 所有同盟的盟主与角色 | 否 |
| 同盟 | 每同盟一个 | 本同盟的盟主与角色 | 视角色判断 |
| 本团 | 玩家核心团 | 玩家与核心团角色 | 是 |

- 每个同盟的同盟频道在服务端是独立消息空间，按同盟标识隔离；其他同盟的频道不向玩家广播
- 同盟与本团频道在等待回应时底部显示「【同盟名】职务·角色 正在回复」，世界频道不显示
- 对话不排队，连续发言不会被拦截，回执按完成顺序出现
- 当前实现中世界频道由三方按随机时间轮播战报与宣言（基准约 20 回合，0.5~1.5 倍随机）；改造后改为各角色按自身排期决定是否发声（见第 12 节 E）

## 4. 决策时机

### 4.1 两类触发

| 类型 | 说明 |
| --- | --- |
| 随机时间 | 相邻两次触发之间没有固定间隔；每次触发后在设定区间内随机决定下一次时机（基准间隔的 0.5~1.5 倍），各角色独立排期，避免集体行动 |
| 关键点 | 局势出现需要上层判断的变化时立即触发，优先级高于随机时间 |

### 4.2 决策点即动作边界

「行动前后都让 LLM 决策一次」与「Bot 连着执行」看着冲突，用**决策点就是动作边界**就能说通：

- 一次 LLM 决策产出一份**行动计划**：若干条指令 + 一段发言 + 明确目标
- Bot 在执行计划期间自主处理寻路、逐格移动、占领计数、遭遇战，不逐步询问 LLM
- 再次决策的时机有四类：计划执行完毕、计划失效、关键点到达、随机时间到
- 「行动后决策」落在**计划结束时的复核**上，不按回合复核；同一角色同一回合最多调用一次 LLM

### 4.3 关键点清单

| 关键点 | 触发方 | 是否经 LLM | 说明 |
| --- | --- | --- | --- |
| 随机时间到 | 角色自身 | 是 | 各角色独立排期 |
| 玩家在同盟频道发言 | 玩家 | 是 | 角色按自身立场回应，可能执行也可能婉拒 |
| 玩家在本团频道发言 | 玩家 | 是 | 同一 LLM 通道，核心团角色带忠诚约束，必然照办 |
| 玩家在世界频道发言 | 玩家 | 是 | 只生成对话回复，不产生行动指令 |
| 计划执行完毕（到达、占领成功、待命就位） | Bot | 是 | 行动后复核 |
| 遭遇战 | Bot | 是 | 胜负均触发，败方立即评估撤退或求援 |
| 占领地易手 / 目标失效 / 行军受阻 | Bot | 是 | 合并为一次决策 |
| 团员退场 / 本团全灭 | Bot | 是 | 仅触发团长与大臣 |
| 频道里被其他角色点名 | 其他角色 | 是 | 按是否被提及筛选，避免全员回应 |

当前已接入：随机时间、玩家在三个频道发言。其余 Bot 侧关键点尚未接入，Bot 遇到这些情况仍按自身行为树处理。

### 4.4 合并与抑制

- 同一回合多个关键点合并为一次决策
- 决策进行中到达的新关键点只记入收件箱，不重复发起，本次返回后并入下次
- 相同类型、同一回合内的重复事件去重（同一地块反复易手只记一次）
- 冷却中的角色仍可被关键点唤醒

## 5. 上下文与记忆

每个角色持有自己的私有记忆，请求时与环境上下文拼成一次调用。

### 5.1 两层上下文

| 层 | 内容 | 作用 |
| --- | --- | --- |
| 自身上下文 | 自己下达过的指令、执行结果、自己说过的发言 | 让角色记得自己做过什么、说过什么 |
| 环境上下文 | 世界 / 同盟 / 本团频道其他人的发言与玩家发言 | 让角色接上前文，知道别人在说什么 |

频道上下文按频道分别维护（各取最近 12 条），互不污染；本轮触发的那句单独存放，不重复出现在环境上下文里。

### 5.2 请求结构

```json
{
  "角色": { "名称": "云谦", "同盟": "北庭", "职位": "大臣", "定位": "法师", "性格": "谨慎、多疑", "描述": "……", "对话提示词": "……" },
  "自身上下文": {
    "行动": [{ "回合": 41, "指令": "进攻", "目标": [12, -7], "结果": "已占领" }],
    "发言": [{ "回合": 40, "频道": "同盟", "内容": "……" }]
  },
  "环境上下文": {
    "世界": [{ "作者": "【赤霄】团长·季桓", "回合": 41, "内容": "……" }],
    "同盟": [{ "作者": "玩家", "回合": 41, "内容": "向北推进" }],
    "本团": [{ "作者": "【北庭】武将·沈砺", "回合": 40, "内容": "已到位" }]
  },
  "可见战况": { "己方地块数": 37, "周边敌方单位": [], "可占领候选": [] },
  "本轮触发": { "类型": "玩家指令", "内容": "向北推进" }

```

### 5.3 裁剪规则

| 部分 | 上限 | 裁剪方式 |
| --- | --- | --- |
| 自身上下文 · 行动 | 8 条 | 保留最近，按回合倒序 |
| 自身上下文 · 发言 | 6 条 | 保留最近 |
| 每个频道 | 10 条 | 保留最近，按频道分别计数 |
| 可占领候选 | 24 个 | 按评分排序 |
| 周边敌方单位 | 8 个 | 按距离排序 |

- 上下文带作者名与回合号，角色据此分辨谁在什么时候说了什么
- 只给可见范围内的信息，不注入全图状态
- 作者注释不进入上下文

### 5.4 输出契约

```json
{
  "reply": "一句中文回应",
  "speech": { "channel": "alliance", "text": "……" },
  "orders": [{ "generalId": "card-xxx", "stance": "attack", "target": [13, -8], "reason": "……" }]
}
```

输出与行动指令结构同构，Bot 无需区分指令来源。解析失败或无有效指令时回退模拟 LLM。

## 6. 并发与限流

几十个角色各自排期，必须显式约束，否则会同时向同一密钥发起大量请求、被服务商排队到超时。

| 机制 | 规则 |
| --- | --- |
| 全局并发上限 | 默认 2 路（可配置），协程调用前先取令牌，用完归还 |
| 排队 | FIFO，按到达顺序；同一角色自身串行，无需额外锁 |
| 超时 | 单次 30s，超时按失败处理 |
| 失败降级 | 回退模拟 LLM，并进入冷却（默认 3 回合），避免连续失败刷请求 |
| 发言配额 | 每个频道每回合最多 1 条，超出排队到下一回合，避免多角色同时刷屏 |
| 无忙碌锁 | 玩家发言永远立即写入频道并返回，不因任何角色正在思考而被拒绝 |

## 7. 失败与降级

| 类型 | 使用条件 | 说明 |
| --- | --- | --- |
| 模拟 LLM | 未接入正式 LLM API | 本地确定性解析，按同一套输入输出运行，保证离线可玩、流程可跑通 |
| LLM | 已配置 LLM | 走 OpenAI 兼容 `chat/completions` 接口 |

- 调用超时、返回无法解析或接口失败时，当次决策回退模拟 LLM
- 同一角色连续失败不阻断推演，只影响该角色当次发言
- 降级不影响指令格式，Bot 无需区分指令来源
- 降级信息只记录在服务端日志，不在界面展示
- LLM 配置存于服务端（baseUrl / model / apiKey），apiKey 不下发浏览器，接口只返回「是否已配置」

## 8. 存档

在世界存档中新增 `actors` 段：

```json
{
  "actors": [
    { "cardId": "……", "nextDecisionRound": 47, "cooldownUntilRound": 44,
      "memory": { "orders": [], "speech": [] } }
  ]
}
```

- 存档版本号 +1；旧存档无 `actors` 段时，所有角色 `nextDecisionRound = 0`，进场重新随机排期
- 关键点收件箱属于瞬时事件，不持久化，读档后由 Bot 后续推进重新产生
- 记忆容量与 5.3 的上限一致，超出从头截断
- 角色属性本身与存档解耦：重开世界时全部角色重新进驻，读档时单位状态来自存档

## 9. 代码结构

```
src-server/game/agent/
  actor.ts       角色协程：循环、触发判定、决策应用
  scheduler.ts   回合信号、LLM 令牌信号量、角色收件箱
  context.ts     上下文组装、裁剪、去重
  memory.ts      角色私有记忆（指令记录、发言记录）
  llm.ts         OpenAI 兼容客户端
```

现有组件到目标结构的映射：

| 现有组件 | 目标角色 |
| --- | --- |
| `CommanderAgent`（全局单例，同盟级） | `CharacterAgent`（每角色一个实例，内含 LLM 客户端、记忆、排期） |
| `WarChat`（同盟发言人统一发言） | `ChannelLog`（纯消息存储 + SSE 广播）+ 各角色自行发言 |
| `GameRuntime.maybeAutoCommand` / `maybeWorldChat` | 删除全局排期，改为各角色协程内部排期 |
| `GameRuntime.chatSend` 同步等回执 | 只写入频道并唤醒目标角色，回执经 SSE 推回 |
| `GameRuntime.applyOrders`（全局） | `CharacterAgent.applyDecision`（角色自己的指令） |

协议变更：

- `typing` 事件增加 `actorId`，前端仍按 `author` 展示「XXX 正在回复」
- `chat` 消息增加 `actorId`，供前端区分同一同盟内的不同角色
- 玩家发言接口立即返回，角色回执通过既有 `chat` SSE 事件送达

## 10. 实施顺序

1. 引入协程骨架与回合信号，把现有自动决策迁入协程，行为与现状等价
2. 频道发言迁入协程，按角色身份署名，世界频道由各角色各自排期
3. 私有记忆与上下文组装
4. 关键点事件总线：遭遇战、占领、被夺、受阻、目标失效、全灭、玩家指令
5. 玩家发言改为「落库 + 唤醒 + SSE 回执」，去掉同步等待
6. 存档扩展 `actors` 段与读档重建
7. 全局并发上限、冷却、发言配额

每步结束后跑 type-check 与 build，并用固定种子对照同回合战报，确认确定性未被破坏。
