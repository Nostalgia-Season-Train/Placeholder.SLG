# 大地图行军推演

> 本文只描述当前 Demo 已实现的内容，不包含未落地的设计构想。
> 相关代码：`src-front/game/`、`src-front/components/MapTerrain.vue`、`src-server/`

---

## 1. 功能概述

三同盟的 Bot 在大地图上行军、占领、交战。渲染层使用 Three.js 提供三维地形与行军表现；推演逻辑运行在独立的 Node 服务中，浏览器只负责渲染与发送指令。

本文只描述地图与推演本身。Bot 如何被角色系统驱动、频道对话与决策节奏见《角色系统》。

Demo 同时提供：

- 角色属性：内置初始角色与玩家自建角色驱动角色生成，职位与定位决定是否亲自带兵
- 设置界面：集中管理当前同盟、推演参数、角色属性与 LLM 配置

## 2. 地图

- 尺寸：34 × 34 的尖顶六边形网格，轴向坐标 `(q, r)`，单格半径为 1
- 地形等级 0~5：

| 等级 | 名称 | 通行 | 说明 |
| --- | --- | --- | --- |
| 0 | 荒地 | 可通行 | 干枯平原，几乎没有产出 |
| 1 | 草地 | 可通行 | 基础资源地 |
| 2 | 林地 | 可通行 | 灌木与零散树木 |
| 3 | 丘陵 | 可通行 | 起伏地形 |
| 4 | 山地 | 不可通行 | 岩壁陡峭 |
| 5 | 高山 | 不可通行 | 雪线之上的险峻地形 |

- 地图为固定预制地图：地形基底、城墙链、关口、山脊、河流与湖泊全部写死在 `src-shared/map/presetMap.ts` 的配置中，不提供种子输入与重新生成入口
- 三条分界线自地图中心延伸到边缘，内段为城墙链、链上各留一座关口、外段为三格宽连续高山，把地图切成三块区域，出生点所在区域只靠关口互通
- 河流与湖泊固定配置，带有流动效果，沿岸为河滩地块
- 道路在地形定案后二次生成：从每处出生点按固定邻域顺序寻路，沿可通行地块逐格铺成连续的道路瓦片，一直铺到该区域相邻的两座关口
- 关口作为道路连通节点，路面跨过关卡继续延伸，与相邻区域的道路接成一条，三块区域因此互相贯通
- 路面渲染只保留生成树与不闭合三角的补边，不会连成三角形色块，转弯与 Y 形岔口保留
- 地块与装饰物统一使用 `InstancedMesh`，单次 draw call 批量渲染
- 三处出生点分别位于三块区域内部，各同盟主城设于出生点，小队从主城相邻的可通行地块出发

## 3. 推演模型

逻辑层按 Tick 推进，每个 Tick 所有角色依次行动；Tick 与界面显示的「回合」为同一节拍。核心规则：

- 角色来源：由角色属性生成（见「角色属性」章节），职位为「无」的角色才会进驻地图成为单位
- 单位属性：战力由角色属性的攻击与魔力档位换算（`32 + 攻击档 × 10 + 魔力档 × 7`，低 / 中 / 高对应 1 / 2 / 3），性格参数由性格标签组合累加得到（胆略与行动偏好两个维度，同维度互斥、语义相反的组合跨维度也互斥，见《角色属性》性格一节）
- 移动：每个 Tick 至多移动一个地块；普通地形占 1 个 Tick，丘陵、河滩与关口占 2 个 Tick（进入后原地停留 1 个 Tick），山地与高山不可通行
- 目标选择：AI 下达进攻、防守、待命、撤退或自主行动指令；收到「自主行动」时，Bot 按地块等级、距离、当前归属与性格参数自行挑选具体地块
- 寻路：A*，绕开不可通行地块
- 占领：在目标地块累计占领进度，达到 `max(2, 地块等级 + 1)` 后完成占领
- 交战：敌我单位处于同一地块或相邻地块（6 个周边）时自动进入交战状态，交战期间双方锁定，不能移动与占领
- 战斗回合：一个 Tick 即一个战斗回合，交战双方每回合各进行一次普攻并同时结算；同格敌人优先，其次相邻敌人，多个单位可以围攻同一目标
- 兵力：上限由角色战力与定位换算，普攻伤害同样由战力与定位换算，附带 ±10% 浮动
- 战败：兵力归零者撤退到相邻地块并休整 2 Tick，兵力不回满；休整期间每 Tick 回复 15% 兵力上限
- 主动撤退：交战中的单位收到撤退指令可脱离交战，并获得 2 Tick 脱战保护
- 确定性：随机数使用 `mulberry32` 种子生成器，种子由固定地图种子派生，同一份存档与配置可复现完全一致的推演过程
- 输出：每回合生成只读快照，包含角色、城池、占领表、事件与统计

## 4. 行军节奏与表现

推演节拍可选慢 / 中 / 快，对应 1100 / 650 / 350 毫秒每 Tick。

逻辑层：

- 角色确定新目标或收到新指令后，下一个 Tick 立即迈出第一步，无需积累行动力
- 行军逐 Tick 推进，每 Tick 至多一格，地形占用多个 Tick 时原地等待
- 占领需要持续数个 Tick，战斗失败后需要休整，这两类停顿属于机制行为

渲染层：

- 一格一段：每次移动只播一段直线动画，时长约为一个 Tick 的 70%，播完棋子停在原地，等下个 Tick 再走下一格
- 同一时间只存在一段动画，不存在多格连续滑行；掉头或切换目标只可能发生在 Tick 边界
- 高度随这段动画同步过渡，静止时保留轻微的待机上下浮动
- 行军路径以连线显示，目标地块显示脉动光环
- 棋子头顶显示名称标签，格式为【同盟名】职务·角色（职位为「无」时省略职务段），与世界频道作者名一致，文字颜色随外交关系变化
- 名称下方附兵力条，按当前兵力占上限的比例填充：六成以上为绿色，三成至六成为黄色，三成以下为红色
- 交战中的单位在名称上方显示交叉双剑标记，轻微脉动，脱离交战后消失
- 立绘占位尚未实现，设计见《同盟关系.md》第 6 章

## 5. 外交关系配色

地图上的占领色块、棋子、行军线、目标环、城池与图例统一按「同盟与玩家的关系」着色。关系只有三档，与同盟名称无关；同盟名称与敌友关系在开局页面配置，每个同盟占用一块预置出生区。

| 关系 | 颜色 |
| --- | --- |
| 同盟（我方） | 绿色 |
| 友盟（友方） | 蓝色 |
| 敌盟（敌方） | 红色 |

实现要点：

- 关系与颜色集中定义在 `src-front/game/bot/diplomacy.ts`，是配色的唯一来源
- 名称表由开局配置生成，渲染层从 `world.alliances` 读取，不使用写死的同盟名称
- 填充不透明度 0.58，三档关系直接对应三种颜色，不叠加内框
- 帮助面板中的同盟图例沿用同一套颜色

多同盟体系的目标设计见《同盟关系.md》，当前 Demo 为 1~3 个可配置同盟。

## 7. 设置界面

入口：标题栏「设置」按钮。地图与推演相关配置全部收拢在此，不再有独立的指挥面板。

| 页签 | 可配置项 |
| --- | --- |
| 大地图行军 | 我方同盟（只读，由开局配置决定）、启用自动决策、决策基准间隔（约 5 / 10 / 20 回合，实际按 0.5~1.5 倍随机）、推演速度（慢 / 中 / 快）、重新开局 |
| 角色 | 点击「添加角色」弹出浮动表单新建角色属性（名称、同盟、团、定位、职位、攻击、魔力、性格、描述、对话提示词、作者注释）；列表内每行可「编辑」 |
| 存档 | 命名保存当前进度、读取、删除；列出各存档的回合与时间 |
| LLM | 模式（真实 LLM / 模拟 LLM）、baseUrl、model、apiKey、保存、测试连接；真实 LLM 连接失败时在页签内直接显示错误原因 |

角色表单与开局页面共用同一组件，分两种模式：分配模式显示同盟、团与职位（新游戏的出战角色、地图内角色页签），角色库模式只显示角色属性；两种模式保存成功后都会自动关闭并刷新列表。角色卡带「是否加入对局」标记：未加入的角色只存在于角色库，不生成单位、不启动协程、不参与对话；新游戏可在出战角色与角色库之间添加或移除。

顶部另保留「暂停 / 继续」快捷操作。重新开局会清空当前推演进度与频道消息，地图保持固定预制。

## 10. 角色属性

地图上的角色由角色属性驱动。角色属性是持久化配置数据，与存档解耦：重开世界时全部角色重新进驻，读取存档时单位状态来自存档本身。属性字段规范见《角色系统/角色属性.md》，角色如何读取属性并驱动 Bot 见《角色系统》。

**属性字段**

| 字段 | 说明 |
| --- | --- |
| 名称 / 同盟 | 基础归属信息；同盟取值来自开局配置 |
| 团 | 本团 / 无团，仅我方同盟可分团，决定本团频道上下文归属 |
| 定位 | 武将 / 术武将 / 法师 / 疗愈师，决定属性倾向与前线职责 |
| 职位 | 无 / 团长 / 大臣；只有「无」会亲自带兵，团长与大臣坐镇指挥不上图 |
| 攻击 / 魔力 | 低 / 中 / 高三档，换算为战力 |
| 性格 | 标签组合（胆略：勇猛 / 果敢 / 稳健 / 谨慎 / 怯战；行动偏好：突击 / 拓土 / 固守），累加为侵略性、谨慎度与敌军偏好 |
| 描述 / 对话提示词 / 作者注释 | 背景文本，供角色系统使用 |

**进驻规则**

- 新建世界（服务启动无续档、重新开局）时，按创建顺序遍历全部角色属性，职位为「无」的角色在所属同盟主城旁生成角色单位
- 推演中途新建的角色：保存后立即进驻当前世界并广播快照，暂停状态下同样生效
- 每个同盟主城相邻空位有限，占满后从主城就近寻找可通行地块

**内置角色**

首次启动自动种入 9 名内置角色：每块出生区 1 名大臣（术武将，攻击 / 魔力双高）加 2 名武将（攻击高 / 魔力低）。同盟槽位红：云谦（本团）/ 朔风（本团）/ 烈风（无团），槽位青：江叙 / 寒江 / 听涛，槽位金：岫远 / 狼烟 / 铁衣；我方以外的同盟不分团，团字段固定为空。内置角色与玩家角色同等对待，可在角色页签编辑全部字段，删除界面尚未提供。

同盟名称可在开局页改，角色卡上的同盟只记录槽位（红 / 青 / 金），显示时按开局配置的名称渲染。

**存储与接口**

角色属性保存在 `src-server/data/cards.db`（`node:sqlite`，WAL），与存档库相互独立：

- `GET /api/cards` 列出全部角色属性（按创建时间排序）
- `POST /api/cards` 新建角色属性；职位为「无」时立即进驻地图并推送快照

服务端对字段做校验：定位、职位、档位取值必须来自固定枚举，名称最长 24 字，长文本最长 2000 字。

## 11. 存档

存档保存在服务端，使用 Node 内置的 `node:sqlite`，不引入第三方依赖。数据库文件为 `src-server/data/save.db`，单表 `saves` 存放各槽位记录，`payload` 列保存完整世界快照。

| 类型 | 标识 | 触发时机 | 是否出现在存档列表 |
| --- | --- | --- | --- |
| 手动存档 | 服务端生成的槽位 ID | 设置界面「存档」页签点击保存 | 是 |
| 自动续档 | 固定 `autosave` | 每 5 回合、重开世界、读取存档、服务退出前 | 否 |

**快照内容**

存档为完整运行时快照，恢复后从存档回合继续推演，不依赖种子重放：

- 回合数、占领表、事件日志与事件上限
- 城池与角色的完整状态，含坐标、目标、指令、行军路径、休整与占领进度
- 随机源当前状态，保证恢复后的随机序列与未中断时一致
- 地图种子（固定），恢复时用同一份预制地图
- 世界、同盟与本团频道消息及各频道的自增消息 ID

**恢复时机**

服务启动时若存在自动续档，直接恢复到该存档的回合，日志输出「已恢复自动续档：第 N 回合」；不存在则用预制地图新建世界。读取手动存档会立即覆盖当前世界，并向所有浏览器推送 `reset` 事件。

**接口**

- `GET /api/saves` 列出手动存档（按保存时间倒序）
- `POST /api/saves` 以给定名称保存当前进度
- `POST /api/saves/:id/load` 读取指定存档
- `DELETE /api/saves/:id` 删除指定存档

存档标识只允许小写字母、数字与连字符；非法标识返回 400。数据库启用 WAL，进程退出时关闭连接。

## 12. 前后端架构与启动

推演逻辑运行在独立的 Node 服务中，进程内只维护一个权威世界；浏览器不参与任何规则计算。

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 权威服务 | `src-server/` | 地图生成、回合推演、AI 决策、频道对话、LLM 调用与状态控制 |
| 共享协议 | `src-shared/` | 数据模型、JSON 编解码、频道类型与纯地图工具 |
| 渲染层 | `src-front/game/map/`、`src-front/components/MapTerrain.vue` | Three.js 渲染、输入处理、订阅快照并展示 |

服务端只从 `src-shared/` 取代码，不再依赖 `src-front/`；前端通过 `@shared/*` 别名复用同一份类型与编解码实现。

通信方式：

- REST：读取世界、调整运行状态、重新开局、发送指令与聊天、读写 LLM 配置
- SSE：`/api/events` 推送 `hello / tick / state / chat / reset` 事件；回合推进只发送占领表增量与轻量快照，断线后浏览器自动重连并重新拉取世界

启动方式：

```bash
npm install
npm run dev        # 同时启动 Node 服务（8787）与 Vite 前端
npm run server     # 只启动权威服务
npm run type-check # 前端与服务端类型检查
```

LLM 配置读取顺序：环境变量 `SLG_LLM_BASE_URL` / `SLG_LLM_MODEL` / `SLG_LLM_API_KEY` 作为默认值，设置界面保存后写入 `src-server/data/settings.json`（已在 `.gitignore` 中忽略）。apiKey 只保存在服务端，接口只返回是否已配置。

开发时浏览器通过 Vite 的 `/api` 代理访问服务端。生产构建后 `dist/` 由 Node 服务直接托管：非 `/api` 的 GET 请求按静态文件返回，未命中的无扩展名路径回退到 `index.html`，带哈希的 `/assets/` 资源使用长缓存。因此 `npm run build` 后只需启动 `npm run server`，在同一端口访问界面与接口；产物目录可通过 `SLG_CLIENT_DIR` 覆盖。
