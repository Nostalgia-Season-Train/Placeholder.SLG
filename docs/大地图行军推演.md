# 大地图行军推演

> 本文只描述当前 Demo 已实现的内容，不包含未落地的设计构想。
> 相关代码：`src-front/game/`、`src-front/components/MapTerrain.vue`、`src-server/`

---

## 1. 功能概述

三势力 Bot（角色行动层）与 AI（决策层）共同驱动大地图推演：AI 负责战略决策并把指令下发，Bot 负责寻路、行军、占领与遭遇战等具体执行。渲染层使用 Three.js 提供三维地形与行军表现；推演逻辑运行在独立的 Node 服务中，浏览器只负责渲染与发送指令。

Demo 同时提供：

- AI 决策：定时或遇到重大事件时由 Bot 请求决策，AI 输出行动指令
- 两种 AI 实现：未接入 LLM 时使用模拟 AI，接入后由正式 LLM 决策
- 通讯频道：世界 / 同盟 / 行军日志；所有 AI 对话均在世界或同盟进行，同盟频道同时作为下达指令的入口
- 角色卡：内置初始卡与玩家自建卡驱动角色生成，职位与定位决定是否亲自带兵
- 设置界面：集中管理当前势力、推演参数、自动决策、角色卡、日志显示与 LLM 配置

## 2. 地图

- 尺寸：34 × 34 的尖顶六边形网格，轴向坐标 `(q, r)`，单格半径为 1
- 地形等级 0~5：

| 等级 | 名称 | 通行 | 说明 |
| --- | --- | --- | --- |
| 0 | 荒地 | 可通行 | 干枯平原，几乎没有产出 |
| 1 | 草地 | 可通行 | 基础资源地 |
| 2 | 林地 | 可通行 | 灌木与零散树木 |
| 3 | 丘陵 | 可通行 | 起伏地形 |
| 4 | 山地 | 不可通行 | 岩壁陡峭 |
| 5 | 高山 | 不可通行 | 雪线之上的险峻地形 |

- 山地与高山会自动从寻路节点和占领候选中排除
- 山脉与河流均沿 CatmullRom 脊线生成：山脉脊线核心为高山、外缘为山地，在河滩或水面处断开形成隘口，两端不触及地图边界以保留绕行缺口
- 河流带有流动效果，沿岸生成河滩地块；道路沿地形连接主要区域
- 地块与装饰物统一使用 `InstancedMesh`，单次 draw call 批量渲染
- 三个势力各有一座主城，位于地图中心外围环带，小队从主城相邻的可通行地块出发

## 3. 推演模型

逻辑层按回合推进，每回合所有角色依次行动。核心规则：

- 角色来源：由角色卡生成（见「角色卡」章节），职位为「无」的卡才会进驻地图成为角色单位
- 角色属性：速度 `0.6 ~ 1.0`，战力由角色卡的攻击与魔力档位换算（`32 + 攻击档 × 10 + 魔力档 × 7`，低 / 中 / 高对应 1 / 2 / 3），性格参数由卡面性格标签映射（如「勇猛」提高侵略性、「谨慎」提高谨慎度）
- 行动力：每回合增加自身速度，上限 2；移动按地块移动代价扣除
- 目标选择：AI 下达进攻、防守、待命、撤退或自主行动指令；收到「自主行动」时，Bot 按地块等级、距离、当前归属与性格参数自行挑选具体地块
- 寻路：A*，绕开不可通行地块
- 占领：在目标地块累计占领进度，达到 `max(2, 地块等级 + 1)` 后完成占领
- 遭遇：敌我单位同格时比较战力随机浮动值，败者撤退并休整 2 回合，胜者占领该地块
- 确定性：随机数使用 `mulberry32` 种子生成器，相同地图与种子可复现完全一致的推演过程
- 输出：每回合生成只读快照，包含角色、城池、占领表、事件与统计

## 4. 行军节奏与表现

推演节拍可选慢 / 中 / 快，对应 1100 / 650 / 350 毫秒每回合。

逻辑层：

- 角色确定新目标或收到新指令时，立即补足迈出第一步所需的行动力，当回合出发，不再空等
- 后续行军仍按行动力与速度规则推进
- 占领需要持续数个回合，战斗失败后需要休整，这两类停顿属于机制行为

渲染层：

- 棋子维护待走地块中心队列，按固定速度匀速步行，约 0.55 秒走一格
- 一帧内可连续走过多个路点，避免帧率波动造成突跳
- 队列超过 4 个路点时丢弃最旧的路点，防止推演速度超过动画时出现长时间追赶
- 高度单独平滑跟随目标地块，保留轻微上下浮动
- 行军路径以连线显示，目标地块显示脉动光环

## 5. 外交关系配色

地图上的占领色块、棋子、行军线、目标环、城池与图例统一按「当前玩家势力与目标势力的外交关系」着色。

| 关系 | 填充色 | 边框 |
| --- | --- | --- |
| 我方 | 绿色 | 无 |
| 同盟友军 | 蓝色 | 无 |
| 非敌军非我方 | 红色 | 无 |
| 敌对同盟 | 红色 | 红色内框 |
| 友好同盟 | 红色 | 蓝色内框 |

关系矩阵（玩家势力切换时生效）：

| 玩家势力 | 北庭 | 东川 | 西陵 |
| --- | --- | --- | --- |
| 北庭 | 我方 | 同盟友军 | 敌对同盟 |
| 东川 | 非敌军非我方 | 我方 | 同盟友军 |
| 西陵 | 同盟友军 | 友好同盟 | 我方 |

实现要点：

- 关系与样式集中定义在 `src-front/game/bot/diplomacy.ts`，是配色的唯一来源
- 边框使用独立的六边形环几何体与 `InstancedMesh`，逐实例上色，与填充色解耦
- 填充不透明度 0.58，边框不透明度 0.92，边框略高于填充以避免深度冲突
- 玩家势力切换时，占领色块、城池与棋子即时重新着色
- 帮助面板中的势力图例每行显示势力名称与关系文字，色块带同样的内框效果

## 6. Bot 与 AI 的分工

本项目的「Bot」与「AI」是两个严格区分的层级，不混用：

| 层级 | 定位 | 职责 |
| --- | --- | --- |
| Bot | 角色行动层，类似人脑的潜意识 | 只执行 AI 下达的指令：寻路、行军、占领、遭遇战、休整 |
| AI | 决策层 | 判断局势并给出行动指令；不直接操作地图 |

Bot 不会自行做战略判断。它的行为来源只有两条：

- AI 已经下发的指令（进攻 / 防守 / 待命 / 撤退 / 自主行动）
- 指令为「自主行动」时，Bot 按地块等级、距离、归属与性格参数在 AI 给定的框架内挑具体地块

AI 在两类时机被请求决策：

- 定时：按固定间隔触发，间隔可在设置中调整
- 重大问题：Bot 遇到需要上层判断的局面时请求决策。当前 Demo 仅在定时路径上接入，重大事件触发尚未实现

**两种 AI 实现**

| 类型 | 使用条件 | 说明 |
| --- | --- | --- |
| 模拟 AI | 未接入正式 LLM API | 本地确定性解析，用于离线测试与联调，保证流程可跑通 |
| LLM | 已配置 LLM | 通过 OpenAI 兼容接口请求正式模型决策，解析失败或调用失败时回退模拟 AI |

**通讯频道**

所有 AI 对话只发生在世界或同盟两个频道，不存在单独的指挥界面：

- 世界：三方 AI 共用频道，每 20 回合按势力轮换发送战报与宣言
- 同盟：本方 AI 频道。在此发言等同下达指令，AI 决策后把命令交给 Bot 执行，并把回应发回频道
- 行军：只读的推演事件日志，不是对话频道，最新记录显示在最上方

**LLM 配置**

- 兼容 OpenAI chat/completions 接口，需要 baseUrl、model、apiKey
- 配置保存在服务端，apiKey 不会下发到浏览器，接口只返回「是否已配置」
- 同一份配置同时驱动 AI 决策与频道对话

## 7. 设置界面

入口：标题栏「设置」按钮。地图与推演相关配置全部收拢在此，不再有独立的指挥面板。

| 页签 | 可配置项 |
| --- | --- |
| 大地图行军 | 当前势力、启用自动决策、决策间隔（每 5 / 10 / 20 回合）、推演速度（慢 / 中 / 快）、地图种子、按种子重新生成 |
| 角色 | 新建角色卡（名称、势力、定位、职位、攻击、魔力、性格、描述、对话提示词、作者注释）；列出全部角色卡 |
| 存档 | 命名保存当前进度、读取、删除；列出各存档的回合、时间与种子 |
| 战况日志 | 显示条数（10 / 14 / 20 / 30）、自动滚动到最新 |
| LLM | baseUrl、model、apiKey、保存与配置状态 |

顶部另保留「暂停 / 继续」与「单步」两个快捷操作。重新生成会清空当前推演进度与行军日志。

## 8. 操作说明

- 拖拽：平移视角
- 滚轮：缩放
- 悬停地块：显示地形等级、描述、坐标与地势
- 悬停城池：显示城池归属
- 同盟频道发言：当作指令下发给本方 AI，例如「向北进攻」「全员防守」「待命」「自由行动」；AI 决策后回执发在同频道
- 世界频道发言：与三方 AI 公开对话，不改变 Bot 的指令
- 帮助：标题栏「帮助」按钮，查看地形等级、场景要素、势力外交配色与行军规则

## 10. 角色卡

地图上的角色由角色卡驱动。角色卡是持久化配置数据，与存档解耦：重开世界时全部卡重新进驻，读取存档时单位状态来自存档本身。设计规范见 `docs/角色卡.md` 与 `docs/角色驱动与LLM决策.md`。

**卡面字段**

| 字段 | 说明 |
| --- | --- |
| 名称 / 势力 | 基础归属信息 |
| 定位 | 武将 / 术武将 / 法师 / 疗愈师，决定属性倾向与前线职责 |
| 职位 | 无 / 团长 / 大臣；只有「无」会亲自带兵，团长与大臣坐镇指挥不上图 |
| 攻击 / 魔力 | 低 / 中 / 高三档，换算为战力 |
| 性格 | 标签文本（如「勇猛、忠诚」），映射为 Bot 的侵略性与谨慎度权重 |
| 描述 / 对话提示词 / 作者注释 | 背景文本；对话提示词供 LLM 扮演参考，作者注释不进入 LLM 上下文 |

**进驻规则**

- 新建世界（服务启动无续档、按种子重新生成）时，按创建顺序遍历全部角色卡，职位为「无」的卡在所属势力主城旁生成角色单位
- 推演中途新建的卡：保存后立即进驻当前世界并广播快照，暂停状态下同样生效
- 每个势力主城相邻空位有限，占满后从主城就近寻找可通行地块

**内置卡**

首次启动自动种入 9 张内置卡：每势力 1 名大臣（术武将，攻击 / 魔力双高）加 2 名武将（攻击高 / 魔力低），名称与势力命名规则一致（北庭：云谦 / 朔风 / 烈风，东川：江叙 / 寒江 / 听涛，西陵：岫远 / 狼烟 / 铁衣）。内置卡与玩家卡同等对待，当前未提供编辑与删除界面。

**存储与接口**

角色卡保存在 `src-server/data/cards.db`（`node:sqlite`，WAL），与存档库相互独立：

- `GET /api/cards` 列出全部角色卡（按创建时间排序）
- `POST /api/cards` 新建角色卡；职位为「无」时立即进驻地图并推送快照

服务端对字段做校验：定位、职位、档位取值必须来自固定枚举，名称最长 24 字，长文本最长 2000 字。

## 11. 存档

存档保存在服务端，使用 Node 内置的 `node:sqlite`，不引入第三方依赖。数据库文件为 `src-server/data/save.db`，单表 `saves` 存放各槽位记录，`payload` 列保存完整世界快照。

| 类型 | 标识 | 触发时机 | 是否出现在存档列表 |
| --- | --- | --- | --- |
| 手动存档 | 服务端生成的槽位 ID | 设置界面「存档」页签点击保存 | 是 |
| 自动续档 | 固定 `autosave` | 每 5 回合、重开世界、读取存档、服务退出前 | 否 |

**快照内容**

存档为完整运行时快照，恢复后从存档回合继续推演，不依赖种子重放：

- 回合数、占领表、事件日志与事件上限
- 城池与角色的完整状态，含坐标、目标、指令、行军路径、休整与占领进度
- 随机源当前状态，保证恢复后的随机序列与未中断时一致
- 地图种子，恢复时按该种子重新生成地图
- 世界与同盟频道消息及各频道的自增消息 ID

**恢复时机**

服务启动时若存在自动续档，直接恢复到该存档的回合，日志输出「已恢复自动续档：第 N 回合」；不存在则按环境种子新建世界。读取手动存档会立即覆盖当前世界，并向所有浏览器推送 `reset` 事件。

**接口**

- `GET /api/saves` 列出手动存档（按保存时间倒序）
- `POST /api/saves` 以给定名称保存当前进度
- `POST /api/saves/:id/load` 读取指定存档
- `DELETE /api/saves/:id` 删除指定存档

存档标识只允许小写字母、数字与连字符；非法标识返回 400。数据库启用 WAL，进程退出时关闭连接。

## 12. 前后端架构与启动

推演逻辑运行在独立的 Node 服务中，进程内只维护一个权威世界；浏览器不参与任何规则计算。

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 权威服务 | `src-server/` | 地图生成、回合推演、AI 决策、频道对话、LLM 调用与状态控制 |
| 共享协议 | `src-front/game/api/` | JSON 编解码、REST 客户端与 SSE 事件类型 |
| 渲染层 | `src-front/game/map/`、`src-front/components/MapTerrain.vue` | Three.js 渲染、输入处理、订阅快照并展示 |
| 纯数据内核 | `src-front/game/bot/`、`src-front/game/agent/` | 无框架依赖的推演与 AI 实现，同时被服务端复用 |

通信方式：

- REST：读取世界、调整运行状态、单步、按种子重开、发送指令与聊天、读写 LLM 配置
- SSE：`/api/events` 推送 `hello / tick / state / chat / reset` 事件；回合推进只发送占领表增量与轻量快照，断线后浏览器自动重连并重新拉取世界

启动方式：

```bash
npm install
npm run dev        # 同时启动 Node 服务（8787）与 Vite 前端
npm run server     # 只启动权威服务
npm run type-check # 前端与服务端类型检查
```

LLM 配置读取顺序：环境变量 `SLG_LLM_BASE_URL` / `SLG_LLM_MODEL` / `SLG_LLM_API_KEY` 作为默认值，设置界面保存后写入 `src-server/data/settings.json`（已在 `.gitignore` 中忽略）。apiKey 只保存在服务端，接口只返回是否已配置。

开发时浏览器通过 Vite 的 `/api` 代理访问服务端。生产构建后 `dist/` 由 Node 服务直接托管：非 `/api` 的 GET 请求按静态文件返回，未命中的无扩展名路径回退到 `index.html`，带哈希的 `/assets/` 资源使用长缓存。因此 `npm run build` 后只需启动 `npm run server`，在同一端口访问界面与接口；产物目录可通过 `SLG_CLIENT_DIR` 覆盖。

## 13. 已知限制

- 角色数量由角色卡决定；当前内置卡为每势力 2 名武将，遭遇战为简化模型
- 法师与疗愈师暂作为普通 Bot 单位参战，支援、恢复与控制职能尚未实现
- 大臣、团长仅存在于角色卡数据中，指挥链（指挥团长攻击指定地点等）尚未接入 AI 决策
- 角色卡暂不支持编辑与删除，性格标签仅映射到目标选择权重，逃跑介入等行为树联动尚未实现
