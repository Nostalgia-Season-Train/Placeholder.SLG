角色系统 · 角色单位

角色单位：一个角色一个 LLM

角色单位有独立上下文、独立记忆、独立排期，每回合产出一句话和一份订单，执行层负责把订单走完。 大地图与 RPG 只是给角色换执行壳，决策、频道、记忆与存档照旧。 集群单位（小兵、杂兵）不走这条链路，另见《集群单位与指挥层》。

三层控制 订单即接口 确定性推进 决策回退链 SLG 执行壳 RPG 执行壳 一人一档 关键点触发
决策 与回退 指令 订单写入 执行 状态机推进 战斗 结算 休整 与撤退

1统一模型

无论跑在大地图还是 RPG，角色都只走「触发 → 决策 → 订单 → 执行」这一条链。

三层控制架构

指挥层

盟主（玩家或 LLM）

提出方向、目标与要求，作用是改变决策层的输入，不直接改指令。

决策层

LLM + 角色属性

以角色身份理解局势，产出「一句话发言 + 若干条订单」，每个角色每回合至多一次。

执行层

Bot 状态机

寻路、逐格移动、占领、遭遇战、筑垒、休整，严格按订单执行，不做战略判断。

一条链路，两个壳 执行层是可替换的，决策层不感知场景

新增玩法只需要再写一个执行壳：决策层与订单格式不动，频道、记忆与存档也不用改。 反过来，换掉决策层（真实 LLM、模拟层、未来的本地模型）同样不影响执行壳。

2订单即接口

决策层只说「要做什么」，执行层决定「一步步怎么走」。

订单的形态 大地图订单为现有实现，RPG 订单为扩展计划

// 大地图 · 角色单位：现有
{ generalId, stance: 'attack' | 'defend' | 'hold' | 'retreat' | 'buildFortress' | 'auto', target }

// RPG：扩展，靠 scene 判别，两个执行器各认各的
type RpgOrder =
  | { scene: 'explore'; unitId: string; stance: 'follow' | 'scout' | 'interact' | 'hold' | 'retreat'; target: Coord | null }
  | { scene: 'battle';  unitId: string; stance: 'attack' | 'skill' | 'guard' | 'boost' | 'flee'; targetId: string | null; boost: number }
订单只描述「姿态 + 目标」，不含逐格路径。战斗里的 boost 是 BP 消耗（0–3）， LLM 只决定加几点，能不能加、加完打几下由战斗执行器校验。

介入边界

项规则
介入点只有一个：sim.setOrder()。LLM 给的是「姿态 + 目标」，不是逐格路径
姿态attack / defend / hold / retreat / buildFortress / auto，决定下一 Tick 走向哪条状态分支
寻路不介入：A* 由执行层计算，自动绕开不可通行地形与敌方已建成要塞
移动与占领不介入：逐格移动、地形耗时、占领进度全部由 sim.step() 推进
战斗不介入：同格或相邻即自动交战，普攻、伤害浮动与胜负结算不询问 LLM
工事与资源不介入：建造进度、拆要塞、扣料与补兵计费由推演层结算；资源不足只回传信号
发言只写文本：reply 进对应频道，受每频道每回合 1 条配额限制
推进权留在世界回合循环：状态机不在角色协程里跑，保证寻路与遭遇战的随机数消费顺序不随协程调度漂移， 同一存档可复现同一战报。

3决策层：什么时候决策

决策不是每 Tick 都发生，而是由触发条件放行。

触发时机

玩家发言

最高优先级

立即唤醒、不等回合边界，令牌队列插到队首；不计入发言配额。

关键点

局势变化

遭遇战、占领成功、战败、行军受阻、失地、要塞失守；距上次不少于 20 回合，期间合并。

随机时间

自主决策

开启自动决策时生效，基准间隔的 0.5 ~ 1.5 倍随机，各角色独立排期。

世界发言

仅发言人

每同盟按职位选一名发言人，约 20 回合一次；只出声，不下指令。

RPG 沿用同一套排期，只把关键点种类换成遇敌、濒死、队友倒下与剧情节点。

介入链路 每 Tick 闭环，LLM 只在环上走一步

世界回合循环每 Tick 推进一次；角色协程只在回合边界被放行，判定该不该决策，再组装上下文并调用 LLM。 订单写入单位后，下一个 Tick 由执行层接管，形成闭环。

决策契约 真实层与模拟层输出同一结构

interface DecisionRequest {
  kind: 'dialogue' | 'explore' | 'battle' | 'advice'
  actorId: string
  context: unknown        // 各场景的上下文组装器生成，只换内容不换结构
  deadlineMs: number      // 本次调用允许等待的上限
  epoch: number           // 世界回合 / 战斗回合，用于丢弃迟到结果
}

interface Decision<T> {
  payload: T              // { reply, orders }，与现有 ActorDecision 同形
  source: 'llm' | 'mock'
  latencyMs: number
  fallbackReason?: 'timeout' | 'network' | 'http' | 'invalid' | 'circuit'
  raw?: string            // 真实层原始输出，便于事后对比
}
输出仍然只有「说什么 + 下达什么指令」。数值、伤害、命中一律由执行层结算， 决策层既看不到也改不了。

4决策层：失败如何回退

回退链包在 LLM 调用外面，执行层完全无感：拿到的永远是同一份订单。

触发条件与处理 默认策略，均可在运行时调整

触发判定处理影响范围
超时 超过 deadlineMs 仍未返回 中止请求，立即用模拟结果 本次调用
网络 / 服务错误 DNS、连接重置、429、5xx、CORS 被拒 回退并计入熔断失败次数 本次调用 + 健康统计
配置错误 401 / 403、模型不存在 回退并持续降级，提示检查设置 该配置修订前
输出非法 解析失败、缺字段、动作不可用 先尝试一次修复，仍失败则回退 非法单位或整份决策
熔断打开 窗口内失败达到阈值 跳过真实层，直接走模拟 冷却窗口内的全部调用
结果过期 返回时 epoch 已变化 丢弃结果，不回写状态 本次调用
现有实现只在角色层做「失败后冷却 3 回合」，粒度粗且每次都要先等超时。RPG 的决策层把这些判断收在一处。

超时预算 截止时间就是玩家可见的最长等待；到点必回退

场景默认截止可调范围理由
对话回复6s3–10s玩家在读字，容忍度较高
探索指令3s1–8s角色自己的节奏，玩家不等，超时照常推进
战斗指挥2s1–5s玩家在等这一回合，必须快
战前 / 战后建议3s1–8s异步补充，超时直接出模板
战斗指挥的等待发生在决策门，地图动画与已有战斗日志照常刷新，不阻塞推演循环。

熔断状态机

关闭

closed

正常调用真实 LLM；成功即清零失败计数。

打开

open · 默认 30s

窗口内失败达到 3 次后打开，期间全部请求直接走模拟层。

半开

half-open

冷却结束只放行 1 个探测请求：成功则回到关闭，失败则继续打开。

配置变更（API Key、baseUrl、模型）时重置熔断状态，避免修好配置后仍被旧状态挡住。

必须守住的约束

不阻塞协程

actor / runtime

只在决策门等待，世界回合、地图动画与渲染保持运行。

真中止请求

AbortController

超时后取消 HTTP，而不是放任连接跑完，避免并发与费用失控。

按 epoch 丢弃

stale guard

迟到结果不得覆盖已经用兜底决策结算过的回合。

部分回退

granularity

个别单位动作非法时只替换该单位，不整份作废。

来源可观测

provenance

每次决策记录来源、耗时、回退原因与熔断状态。

模拟层确定性

mock

只用快照与回合数取模板，不引入随机，保证可复现。

5执行壳 A：大地图 Bot

GeneralState.status 七个取值，每 Tick 对未锁定、未休整的单位调用一次 act()。

状态图 实线为常规转移，虚线为指令或打断

待命 / 行军 / 占领 / 驻守 任一处出现同格或相邻敌军都会转入交战（休整中与 2 Tick 脱战保护期内除外）；交战锁定的单位当 Tick 不移动、不占领，只结算一次普攻。
到达己方地块或主城格直接转驻守；主城格只由小兵破城改归属，角色不占领。
筑垒被打断（换指令、主动撤退、战败撤退、资源不足）会清空半成品，进度与已扣资源都不返还。

状态转移表

状态怎么进入当 Tick 做什么 / 怎么离开
休整 resting 战败（兵力归零）后退到相邻空格，restTurns = 2 每 Tick 回复 15% 兵力上限，按恢复量扣粮食与黄金，不足则少回；restTurns 归零后按指令或重新选点
待命 idle 无指令、无目标，或目标失效、筑垒非法、资源不足导致指令被清空 自主选点（性格权重 + 地块价值，排除主城与要塞格）→ 行军；收到 hold 指令 → 驻守
行军 marching 有待执行的目标，来自订单或自主选点 逐 Tick 走一格，丘陵 / 河滩 / 关口原地多等 1 Tick；下一格是敌方已建成要塞时原地等待拆要塞
占领 capturing 站在目标格上，该格不属于自己、且不是主城格 每 Tick 进度 +1，达到 max(2, 等级 + 1) 后地块易手 → 驻守，并发出「占领」关键点
驻守 garrison hold 指令；抵达己方格或主城格；占领完成；要塞建成 持 hold 指令时持续驻守；否则下一 Tick 无目标时重新选点 → 行军
交战 fighting 同格或相邻出现敌方单位（休整中、2 Tick 脱战保护期内除外），单位被锁定 兵力归零 → 休整；收到 retreat 指令 → 脱战退一格并获得 2 Tick 保护；敌军消失 → 解除锁定，回到原流程
筑垒施工 building buildFortress 指令站上道路或关口目标，且资源足够 开工扣石料 80 + 木材 60；进度达到 18 / 12 / 8 建成 → 驻守；被打断则清空

6执行壳 B：RPG 探索与战斗

同一套「状态 + 订单 + 每回合推进」，换成方形网格与回合制战斗。以下为计划设计，尚未落代码。

探索状态链 场景内移动，遇敌切场景

探索层只管「走格子、踩触发格、进战斗」。方形网格用 4 向移动，每格耗时同大地图； 交互与对话期间单位不动，战斗结束回到遇敌格并给一次短暂无敌，避免立刻二次遇敌。

战斗回合环 1 回合 = 1 次行动，BP 与护盾跨回合保留

两个执行器的状态对照

执行器状态每回合做什么
探索 待命 / 行军 / 交互 / 遭遇 / 战斗 按订单选点并逐格移动；踩到 NPC 或物件格转入交互；明雷进入相邻格转战斗
战斗 回合开始 / 决策与指令 / 行动结算 / 破防与护盾 / 回合结束 BP 每回合 +1（上限 5），单次最多花 3；弱点命中削盾，破防后跳过下一次行动且受伤 ×1.5
战斗执行器只消费订单里的「行动 + 目标 + BP 消耗」，连击次数、伤害、命中与破防判定全部由结算层决定。

7两种壳的边界

哪些照搬、哪些只加分支、哪些必须新写，一张表定死。
